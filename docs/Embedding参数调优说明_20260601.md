# Embedding参数调优说明

> 本文档解释RAG系统中各参数的「为什么」，以及我们做过哪些实测验证
> 适用：理解RAG调参逻辑，面试能讲清楚
> 日期：2026-06-01

## 一、参数全景图

```
用户提问
  ↓
① vectorStore.similaritySearch(query, topK, similarityThreshold)
  ↓
② filterByRelativeScore() ← 自定义三级过滤
    ├── 绝对值兜底: top1 < 0.45 → 拒绝
    ├── 无区分度检测: distinct gap < 0.05 && top1 < 0.6 → 拒绝
    └── 15%分差保留: score > top1 * 0.85
  ↓
③ 结果注入System Prompt → LLM生成回答
```

---

## 二、为什么用 similarityThreshold=0.3

### 2.1 设计意图

`similarityThreshold` 是PgVector搜索时的**底层过滤**——cosine相似度低于此值的向量直接排除。

### 2.2 实测数据

| 查询 | nomic分数 | BGE分数 | 是否应保留 |
|------|----------|---------|-----------|
| 退换货政策 | 0.739 | **0.680** | ✅ 保留（>0.3）|
| 积分 | - | **0.657** | ✅ 保留（>0.3）|
| 包邮吗 | - | **0.629** | ✅ 保留（>0.3）|
| 今天天气 | 0.622 | **0.383** | ⚠️ 保留但后续被规则过滤 |

### 2.3 为什么是0.3而不是0.5

**踩过的坑**：最初设0.5（nomic时代的值），但BGE整体分数偏低。BGE的相关查询最高才0.68，设0.5会丢失部分相关结果。

**选0.3的理由**：
- 低于所有相关查询的分数（0.62+ → 全部保留）
- 不相关查询（0.38）虽然通过，但后续 `filterByRelativeScore` 会拦截
- 两层过滤：**第一层宽松保召回，第二层严格保精确**

**面试话术**：
> "similarityThreshold设0.3是故意的——搜宽一点让二次过滤去判断。如果设高了，相关文档可能被漏掉；设低了顶多多几个无关片段，二次过滤会处理。宁可多搜不可漏搜。"

## 三、为什么用 topK=5

### 3.1 设计意图

`topK` 控制向量最相似的前N个文档。

### 3.2 实测数据（BGE）

```
查询「退换货政策」的Top-5分数分布：
1. 0.6800 ← 退换货正文章节
2. 0.6800 ← 同上（切片重叠）
3. 0.6800 ← 同上（切片重叠）
4. 0.6776 ← 退换货流程 
5. 0.6277 ← 质量运费相关
```

### 3.3 为什么是5不是3

- Top3全是退换货内容，再加2条可以覆盖质量运费等**边缘相关**信息
- LLM可以综合判断——比如用户问"退货有什么条件"，除了7天无理由，还可能有质量问题的特殊政策
- topK越小推理越快，但**面试更容易展示"全面考虑"的思维**

### 3.4 冗余切片问题

切片重叠（`OverlappingTextSplitter` 的10% overlap）会导致Top-N里出现**相同内容的不同切片**。虽然浪费了位置，但保证了边界语义不丢失。这是**用空间换正确性**的权衡。

## 四、为什么用相对分数过滤（三层逻辑）

`filterByRelativeScore()` 是自定义的三级过滤，它的设计来源于对nomic和BGE两种模型的实测。

### 4.1 第一层：绝对值兜底（top1 < 0.45 → 拒绝）

**为什么需要**：BGE的不相关查询能低到0.16，但某些不相关也会到0.38。设0.45作为硬红线——低于此值就算Top-5里全是这个分数，也不值得让LLM回答。

**实测验证**：

| 查询 | BGE Top1 | 是否通过 | 说明 |
|------|---------|---------|------|
| 今天天气 | 0.383 | ❌ 拒绝 | 正确驳回 |
| 退换货 | 0.680 | ✅ 通过 | 正确保留 |
| 积分 | 0.657 | ✅ 通过 | 正确保留 |

### 4.2 第二层：无区分度检测

**原版问题（nomic）**：
nomic对完全不相关的文本也打出0.55-0.70的分数，Top1和Top2分差极小（比如0.602和0.597）。这说明模型本身没有区分能力，此时返回的任何文档都是噪声。

**BGE版改进**：
BGE区分度更好，但 `OverlappingTextSplitter` 导致切片重叠——同一个内容的多个切片分数完全相同（如0.680出现3次）。这会导致gap=0，触发原本的"无区分度"误杀。

**改了什么**：
- 旧：`gap < 0.08 && top1 < 0.75 → 拒绝`
- 新：**先去重（distinct），再算gap；gap < 0.05 && top1 < 0.6 → 拒绝**

| 场景 | 旧逻辑 | 新逻辑 |
|------|--------|--------|
| 切片重叠（3个0.680） | gap=0 → ❌误杀 | 去重后只剩1个0.680 → ✅ 正常 |
| 真正无区分（0.42, 0.40, 0.39） | gap=0.02 → ❌不过 | gap=0.02且top1<0.6 → ✅ 正确拒绝 |

### 4.3 第三层：分差保留（score > top1 × 0.85）

只保留与最高分相差15%以内的文档。这一层是为了去掉**明显不如Top1好的结果**。

例如：

```
Top1=0.680 → 保留阈值=0.578
结果：0.680, 0.680, 0.678, 0.627 → 全部保留（>0.578）
结果5 = 0.301 → 过滤（<0.578）
```

### 4.4 三层过滤的效果

| 查询 | 原始Top5 | 一级(0.45) | 二级(gap) | 三级(85%) | 最终 |
|------|---------|-----------|-----------|----------|------|
| 退换货 | 5条 | ✅ | ✅ | 保留Top3 | ✅ 3条 |
| 今天天气 | 5条 | ❌ 0.383 | - | - | ❌ 0条 |
| 积分 | 5条 | ✅ 0.657 | ✅ | 保留Top3 | ✅ 3条 |

## 五、BGE vs nomic 参数差异总览

| 参数 | nomic值 | BGE值 | 为什么BGE要改 |
|------|---------|-------|--------------|
| similarityThreshold | 0.5 | **0.3** | BGE分数整体偏低 |
| topK | 3 | **5** | BGE排序更合理，多取几条收益高 |
| 绝对兜底阈值 | 0.45 | **0.45** | 不变，BGE不相关可低至0.16 |
| gap阈值 | 0.08 | **0.05** | BGE区分度好，gap可以更小 |
| gap触发上限 | 0.75 | **0.6** | 适配BGE分数分布 |
| 去重逻辑 | 无 | **有** | 切片重叠导致相同分数 |

## 六、为什么这些参数不能"一套走天下"

**核心原因：不同Embedding模型的分数分布不同。**

| 模型 | 分数范围 | 区分度 |
|------|---------|--------|
| nomic-embed-text | 0.35 ~ 0.75 | 差（全挤在0.55-0.70） |
| bge-large-zh-v1.5 | 0.16 ~ 0.74 | 好（分布拉开） |
| text-embedding-ada-002 | 0.70 ~ 0.95 | 好（但付费） |

换模型必须重新标定阈值。这也是为什么我们的代码用**相对分数**而非**绝对分数**作为主要过滤手段——相对策略对模型更换的容忍度更高。

**面试话术**：
> "RAG的检索参数不能复制粘贴。每个Embedding模型的分数分布不同——nomic的0.6可能对应BGE的0.3。我换BGE的时候重新测了一遍Top-K的分数分布，确认相关/不相关的分界线，然后才调整了阈值。调参的核心思路是：阈值松一点保证召回，二次过滤严格一点保证精确——宁可多搜不让漏。"
