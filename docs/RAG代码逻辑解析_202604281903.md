# RAG 代码逻辑深度解析（2026-04-26 起持续更新）

> 基于对话中逐行分析 spring-ai-demo 的 RAG 流程整理。
> 面向"理解原理后才知道怎么优化"的学习目标。
> **当前架构**：Embedding=Ollama本地，VectorStore=PgVectorStore（PostgreSQL持久化），Chat=DeepSeek

---

## 一、RAG 是什么（一句话）

**RAG = Retrieval-Augmented Generation = 检索增强生成**

本质：大模型不懂你的私有数据（公司文档、产品手册等），所以先从数据库里检索出相关内容，再让大模型基于检索到的内容来回答。

```
没有 RAG：  用户问题 ──────────────────────→ 大模型 → 可能瞎编
有 RAG：    用户问题 → 检索相关文档 → 大模型 → 基于文档回答
```

## 三、离线阶段：上传 PDF 逐行解析

### 3.1 入口：RagController.upload()

```java
@PostMapping("/upload")
public String upload(@RequestParam("file") MultipartFile file) {
    // MultipartFile：Spring MVC 接收的上传文件对象
    String result = ragService.uploadDocument(file);
    return result;
}
```

### 3.2 RagService.uploadDocument() 逐行分析

**第1步：保存 PDF 到本地（第60-68行）**

```java
String uploadDir = "D:\\test";
File dir = new File(uploadDir);
if (!dir.exists()) dir.mkdirs();

String originalFilename = file.getOriginalFilename();  // 获取原始文件名
String savedFilename = System.currentTimeMillis() + "_" + originalFilename;  // 加时间戳防重名
File savedFile = new File(dir, savedFilename);
file.transferTo(savedFile);  // 保存到 D:\test\{时间戳}_xxx.pdf
```

> **踩坑记忆**：之前用 `Files.createTempFile()` 临时文件，被系统提前清理导致 "does not exist"。改用固定目录解决。

**第2步：读取 PDF（第73-76行）**

```java
PagePdfDocumentReader reader = new PagePdfDocumentReader(
    new FileSystemResource(savedFile.toFile())
);
List<Document> documents = reader.get();
```

**`PagePdfDocumentReader` 内部做了什么**：
1. 使用 Apache PDFBox 打开 PDF 文件
2. 逐页提取文本内容
3. 每页创建一个 `Document` 对象
4. `Document` 结构：
   ```java
   Document {
       text: "这一页的文本内容...",
       metadata: {
           "pdf.resource.name": "xxx.pdf",     // 文件名
           "page.number": 0,                     // 页码（从0开始）
           "source.application": "pdf-reader"    // 来源标记
       },
       id: "自动生成的UUID",
       embedding: null  // 这时候还没有向量
   }
   ```

**举例**：一个 10 页的 PDF → `documents` 有 10 个元素，每个元素是一页的内容。

**第3步：文本切分（第80-81行）**

```java
TokenTextSplitter splitter = new TokenTextSplitter();
List<Document> chunks = splitter.apply(documents);
```

**`TokenTextSplitter` 的默认参数**（代码中没设，全用默认值）：
```java
defaultChunkSize = 800      // 每段最多 800 个 Token
defaultOverlap = 0           // ⚠️ 段与段之间没有重叠！
minChunkSizeChars = 350      // 最小字符数（防止切出太短的片段）
maxNumChunks = 10000         // 最大分片数（防止超大文档内存溢出）
```

**切分示意**（overlap=0 的问题）：
```
原文（1200 Token 的一段话）：
[═══════════════════════════════════════════════════]

切分后：
chunk1 [════════════════════════════]  ← 前 800 Token
chunk2 [════════════════════]          ← 后 400 Token

问题：第 800 Token 附近可能正好把一句话拦腰截断！
比如："Spring AI 提供了对话、Embedding、向量存储等功 | 能..."
                                                            ↑ 断在这里
chunk1 尾部："...向量存储等功"
chunk2 开头："能。用户可以通过简单的配置快速接入..."
→ "功" 和 "能" 被拆开了，语义不完整
```

**举例**：10 页 PDF → 切分后可能有 30-50 个 chunks（取决于每页的 Token 数量）。

**第4步：向量化并存储（第85行）**

```java
vectorStore.add(chunks);
```

**这一行代码内部做了很多事**（SimpleVectorStore 源码简化版）：

```java
// VectorStore.add() 内部实现
public void add(List<Document> documents) {
    for (Document doc : documents) {
        // 1. 把文本转向量
        float[] embedding = embeddingModel.embed(doc.getText());
        doc.setEmbedding(embedding);
        
        // 2. 存入内存 Map
        store.put(doc.getId(), doc);
    }
}
```

**`embeddingModel.embed()` 内部**（OllamaEmbeddingModel）：

```
"Java是一门面向对象的语言"
        │
        ▼
POST http://localhost:11434/api/embed
{
    "model": "nomic-embed-text",
    "prompt": "Java是一门面向对象的语言"
}
        │
        ▼
返回 [0.12, -0.34, 0.56, ..., 0.78]  （768个浮点数）
```

**存储结果**（SimpleVectorStore 就是内存里的 Map）：

```
Map<String, Document> store = {
    "uuid-1" → Document(text="...", embedding=[0.12, -0.34, ...], metadata={...}),
    "uuid-2" → Document(text="...", embedding=[0.45, 0.22, ...], metadata={...}),
    ...（30-50 个条目）
}
```

### 4.2 RagService.askQuestion() 逐行分析

**第1步：向量检索（第96-101行）**

```java
List<Document> relevantDocs = vectorStore.similaritySearch(
    SearchRequest.builder()
        .query(question)    // 用户原始问题
        .topK(5)            // 返回最相似的 5 个片段
        .build()
);
```

**`similaritySearch()` 内部实现**：

```java
public List<Document> similaritySearch(SearchRequest request) {
    // 1. 把问题也转向量
    float[] queryVector = embeddingModel.embed(request.getQuery());
    
    // 2. 遍历内存中所有已存储的文档
    return store.values().stream()
        // 3. 计算每个文档与问题的余弦相似度
        .map(doc -> {
            double score = cosineSimilarity(queryVector, doc.getEmbedding());
            return new AbstractMap.SimpleEntry<>(doc, score);
        })
        // 4. 按相似度从高到低排序
        .sorted((a, b) -> Double.compare(b.getValue(), a.getValue()))
        // 5. 取 Top 5
        .limit(request.getTopK())
        // 6. 返回文档（不含分数）
        .map(Map.Entry::getKey)
        .collect(Collectors.toList());
}
```

**余弦相似度的直觉理解**：

```
两个向量在空间中的方向越一致 → 相似度越高

"什么是Spring AI" 的向量     →  [0.11, -0.33, 0.55, ...]
"Spring AI是Java的AI框架" 的向量 → [0.12, -0.34, 0.56, ...]  → 相似度 0.95 ✅ 相关

"什么是Spring AI" 的向量     →  [0.11, -0.33, 0.55, ...]
"今天深圳天气很好" 的向量     →  [0.89, 0.12, -0.67, ...]  → 相似度 0.02 ❌ 不相关
```

**⚠️ 当前代码的问题**：没有设置 `.similarityThreshold()`，意味着即使 5 个结果都不相关（相似度很低），也会全部拼给 DeepSeek。

**第2步：拼装上下文（第105-107行）**

```java
String context = relevantDocs.stream()
    .map(Document::getText)
    .collect(Collectors.joining("\n\n---\n\n"));
```

把 5 个文档片段的纯文本用分隔符连成一个长字符串：

```
"Spring AI 是一个应用框架...\n\n---\n\n它提供了对话、Embedding...\n\n---\n\n..."
```

**第3步：调用 DeepSeek 生成回答（第110-117行）**

```java
String content = chatClient.prompt()
    .system("你是一个专业知识库助手。请严格基于以下参考资料回答用户问题。" +
            "如果参考资料中没有相关信息，请明确告知用户。" +
            "不要编造参考资料之外的内容。\n\n" +
            "参考资料：\n" + context)
    .user(question)
    .call()
    .content();
```

**发给 DeepSeek 的完整请求**：

```
POST https://api.deepseek.com/v1/chat/completions

{
    "model": "deepseek-chat",
    "messages": [
        {
            "role": "system",
            "content": "你是一个专业知识库助手。请严格基于以下参考资料回答用户问题...\n\n参考资料：\nSpring AI 是一个应用框架...\n\n---\n\n它提供了对话、Embedding..."
        },
        {
            "role": "user",
            "content": "什么是Spring AI"
        }
    ],
    "temperature": 0.7
}
```

**DeepSeek 收到后的处理**：
1. 读取 system 中的参考资料
2. 分析用户问题
3. 从参考资料中找到相关信息
4. 组织语言回答
5. 如果参考资料中没有相关信息，按指令回复"参考资料中没有..."

## 五、问答不准确的根因分析

| # | 根因 | 代码位置 | 影响 | 优先级 |
|---|------|----------|------|--------|
| 1 | **切分无重叠**（overlap=0） | RagService 第80行 `new TokenTextSplitter()` | 关键信息被截断，语义碎片化 | ⭐⭐⭐ 最高 |
| 2 | **无相似度阈值** | RagService 第98行 `SearchRequest` | 不相关片段也传给模型，干扰回答 | ⭐⭐⭐ 最高 |
| 3 | **System Prompt 过于简单** | RagService 第110-114行 | 没引导模型处理矛盾信息、引用来源 | ⭐⭐ 中 |
| 4 | **Embedding 模型轻量** | 启动类 nomic-embed-text | 中文语义精度可能不够 | ⭐ 低（先调参数再换模型） |

### 优化方案速查

```java
// 优化1：TokenTextSplitter 加 overlap
TokenTextSplitter splitter = TokenTextSplitter.builder()
    .defaultChunkSize(800)
    .defaultOverlap(200)          // 200 Token 重叠
    .minChunkSizeChars(200)
    .build();

// 优化2：相似度阈值
SearchRequest.builder()
    .query(question)
    .topK(5)
    .similarityThreshold(0.7)     // 只取相似度 >= 0.7 的结果
    .build();

// 优化3：更好的 System Prompt
.system("""
    你是一个专业知识库助手。请严格基于以下参考资料回答用户问题。
    回答规则：
    1. 只使用参考资料中的信息，不要编造
    2. 如果参考资料不足以回答，请明确说明
    3. 引用来源时标注出处（如"根据资料第X部分"）
    4. 如果多个资料有矛盾，以最新日期的资料为准
    
    参考资料：
    """ + context)
```

## 六、数据流一句话总结

```
PDF → 按页读(10页→10个Document) → 切成800Token片段(overlap=0)
     → 每片段转向量(768维,Ollama本地) → 存入 PgVectorStore（PostgreSQL持久化）

提问 → 问题转向量 → pgvector 数据库余弦相似度检索 → 取Top5(无阈值)
     → 拼成参考资料 → DeepSeek回答(严格基于资料)

注意：已从 SimpleVectorStore（内存）迁移到 PgVectorStore（PostgreSQL），
数据持久化到 vector_store 表，重启不丢失。
```

面试时如果被问"你的 RAG 是怎么实现的"，按这个数据流讲就行，配合优化方案，能体现深度思考。
