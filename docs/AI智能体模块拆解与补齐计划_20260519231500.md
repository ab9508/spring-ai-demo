## 二、已实现模块（8个）

### 1. LLM接入层
- **实现方式**：双模型配置（Ollama本地 deepseek-r1:8b + DeepSeek API），通过 `app.chat.provider` 开关切换
- **关键文件**：`config/ChatClientConfig.java`
- **亮点**：`@ConditionalOnProperty` + `@Primary` 解决多Bean歧义，exclude OpenAiEmbeddingAutoConfiguration 避免Embedding冲突

### 2. 提示词工程
- **实现方式**：五要素完整system prompt（角色定义/能力边界/行为规则/输出格式/禁止事项）
- **关键文件**：`controller/AgentController.buildSystemPrompt()`
- **亮点**：不是泛泛的"你是一个助手"，而是电商客服场景的精确约束

### 3. 记忆系统
- **实现方式**：Redis持久化 + 摘要压缩，装饰器模式三层嵌套
- **关键文件**：
  - `config/RedisChatMemoryRepository.java`（手写Redis存储，含Tool Calling序列化）
  - `memory/SummarizingChatMemory.java`（超20条自动LLM压缩）
  - `config/RedisChatMemoryConfig.java`（Bean装配）
- **亮点**：Spring AI 1.0.x原生不支持Redis，手写实现；DTO中间层解决Message子类无默认构造的Jackson反序列化问题；支持ToolResponseMessage完整序列化

### 4. 工具系统（Tool Calling）
- **实现方式**：`@Component` + `@Tool(description)` 注解方法，查DB真实数据
- **关键文件**：`tool/OrderTools.java`（3个工具：queryOrder/queryStock/handleAftersale）
- **亮点**：不是mock数据，真实查询PostgreSQL；模糊搜索（先精确ID→再名称LIKE→再列表摘要）

### 5. RAG知识库
- **实现方式**：自定义Advisor + PgVector + 相对分数过滤 + 多格式文档上传
- **关键文件**：
  - `advisor/CustomRagAdvisor.java`（before阶段向量检索+上下文注入，含相对分数过滤）
  - `transformer/OverlappingTextSplitter.java`（两层切片法+滑动窗口overlap）
  - `service/RagService.java`、`controller/RagController.java`
- **亮点**：相对分数过滤（top1<0.45拒绝 + top1-top2<0.08无区分度拒绝 + 15%衰减保留）；两层切片法解决语义边界断裂

### 6. MCP集成
- **实现方式**：Server端（@Tool→JSON-RPC SSE暴露）+ Client端（远程工具自动注入ChatClient）
- **关键文件**：
  - `config/McpServerConfig.java`（条件激活）
  - `controller/McpClientController.java`（ToolCallbackProvider自动装配）
  - `application-mcp-server.yml`、`application-mcp-client.yml`
- **亮点**：WebMVC版Starter（非WebFlux），解决Tomcat下SSE路由不注册的踩坑
- **状态**：代码已写完，**尚未跑通验证**

### 7. 结构化输出
- **实现方式**：纯净ChatClient（无工具无记忆）+ JSON prompt + 手动清洗 + Jackson反序列化
- **关键文件**：`controller/AgentController.analyzeIntent()`、`cleanJsonResponse()`
- **亮点**：解决Tool Calling与结构化输出冲突（带工具的Client→DeepSeek优先调工具而非返回JSON）；cleanJsonResponse处理markdown包裹/前后文杂字

### 8. 流式输出
- **实现方式**：SSE（`Flux<String>` + `text/event-stream`），同步/流式双接口
- **关键文件**：`controller/AgentController.chatStream()`
- **亮点**：流式中仍能获取完整ChatResponse元数据（model/finishReason/usage）

## 三、部分实现模块（3个）

### 1. 规划推理（Planning & Reasoning）

| 子能力 | 现状 | 差距 |
|--------|------|------|
| 单步Tool Calling | 已实现 | — |
| 多步推理链 | 框架支持（LLM可连续调多个Tool），但没有显式编排 | 缺少ReAct/Plan-then-Execute显式流程 |
| 任务分解 | 无法把复杂任务拆成子步骤 | 需要手写Chain/Workflow |
| 推理反思 | 无 | 需要LLM自我评估输出质量 |

**补齐方向**：实现ReAct循环（Thought→Action→Observation→Thought...），在Advisor层做
**面试价值**：体现对Agent深层理解，区别于"只会调API"

### 2. 安全与合规（Safety & Guardrails）

| 子能力 | 现状 | 差距 |
|--------|------|------|
| 输入过滤 | prompt里写了"禁止无关指令"，仅软约束 | 缺硬编码输入拦截（敏感词/Prompt注入检测） |
| 输出过滤 | prompt约束输出格式，无后置校验 | 缺输出内容审核（敏感信息泄露检测） |
| 工具权限 | 所有工具对所有用户开放 | 缺按用户/角色限制可用工具 |
| Prompt注入防护 | 无 | 缺系统指令提取检测 |

**补齐方向**：写一个GuardrailsAdvisor（before做输入校验，after做输出审核）
**面试价值**：面试必问"生产环境怎么保证安全"，有代码=大加分

### 3. 可观测性（Observability）

| 子能力 | 现状 | 差距 |
|--------|------|------|
| Token用量日志 | CustomRagAdvisor.after()已记录 | — |
| 耗时监控 | Controller层手动T1/T2 | 缺Micrometer/Prometheus指标集成 |
| 工具调用追踪 | OrderTools里打日志 | 缺traceId串联调用链 |
| 对话质量评估 | 无 | 缺feedback loop（用户评分/自动评估） |
| 异常监控 | 无 | 缺告警机制 |

**补齐方向**：Micrometer集成 + 结构化日志（traceId） + 简单的对话质量统计
**面试价值**：体现工程化思维

## 四、未实现模块（1个）

### 多Agent编排

- **现状**：单Agent架构（一个ChatClient + 一套工具）
- **差距**：无多Agent协作（如主Agent+子Agent分工、Agent间消息传递、任务分发与合并）
- **面试价值**：锦上添花，中小公司很少需要
- **结论**：优先级最低，暂不补齐
