## 2. 新开AI项目 —— 业务与技术栈

### 2.1 业务方向对比

| 方向 | 业务价值 | 技术差异化 | 推荐度 |
|------|---------|------------|--------|
| **内部知识库问答**（公司文档/工单） | 高频刚需，可量化 | RAG 深化：重排序/混合检索/多路召回 | ⭐⭐⭐⭐⭐ |
| **日志/告警智能分析** | Ops 场景，展示广度 | LLM + 结构化日志解析 + 告警聚合 | ⭐⭐⭐⭐ |
| **SQL 生成/数据查询助手** | 数据场景 | LLM + SQL 执行 + 结果校验（Text2SQL） | ⭐⭐⭐⭐ |
| **代码审查 AI 助手** | 开发工具 | AST 解析 + Diff 分析 + 规则引擎 | ⭐⭐⭐ |

**推荐：内部知识库问答系统**——业务域不同（电商客服 vs 企业内部知识），技术栈有区分度。

### 2.2 技术栈对比（是否重复）

| 层面 | spring-ai-demo（电商客服） | 新项目（内部知识库） | 重复度 |
|------|---------------------------|---------------------|--------|
| LLM调用 | Spring AI + DeepSeek | **Python + LangChain** | 低 ✅ |
| RAG | PgVector + 基础检索 | **Chroma + 混合检索 + 重排序** | 低 ✅ |
| Agent | Tool Calling + ChatMemory | **Multi-Agent 编排（主管-工人）** | 低 ✅ |
| 数据层 | PostgreSQL | **Elasticsearch（全文检索）** | 低 ✅ |
| 部署 | Docker Compose 本地 | **K8s + 监控（Prometheus/Grafana）** | 低 ✅ |

**结论**：技术栈不重复，展示技术广度，正好弥补「AI项目经验少」。

## 3. 深挖底层机制 —— 增加技术深度

### 3.1 可聊的底层话题（按面试频率排序）

| 话题 | 底层机制 | 面试可以聊什么 | 准备难度 |
|------|---------|----------------|---------|
| **Spring AI ChatClient 架构** | Advisor 责任链、Request/Response 拦截 | "Advisor 链 before/after 执行顺序，@Order 控制逻辑" | ⭐⭐⭐ |
| **RAG 向量检索算法** | HNSW 索引、余弦相似度 | "PgVector 用 HNSW，查询 O(log N)，为什么比暴力搜索快" | ⭐⭐⭐⭐ |
| **Redis 数据结构与持久化** | SDS、跳表（ZSet）、RDB/AOF | "ZSet 用跳表不用平衡树；AOF always/everysec/no 区别" | ⭐⭐⭐ |
| **Transformer Attention** | Self-Attention、QKV、位置编码 | "Attention O(n²)，推理为何要 KV Cache；位置编码解决什么" | ⭐⭐⭐⭐⭐ |
| **MCP 协议设计** | JSON-RPC 2.0、SSE 传输 | "MCP 为何选 JSON-RPC 不是 REST；SSE vs WebSocket 场景" | ⭐⭐⭐⭐ |
| **Tokenization 与 BPE** | Byte Pair Encoding、词表 | "中文用字节级 BPE；token 数和推理成本关系" | ⭐⭐⭐⭐ |

### 3.2 Spring AI ChatClient 底层（最重要，必准备）

```
ChatClient.call() 执行流程：
1. 构建 Prompt
2. Advisor Chain.before()  ← 从后往前执行（栈结构）
3. ChatModel.call()
4. Advisor Chain.after()   ← 从前往后执行（正序）
5. 返回 ChatResponse

Advisor 执行顺序由 @Order 或 order() 控制：
- before 阶段：Order 值大的先执行（后注册的先进入）
- after 阶段：Order 值小的先执行（先注册的先退出）
- 所以配置 "RAG 在前、Memory 在后"，
  实际上 RAG Advisor 的 before 先执行，符合预期
```

## 4. Spring AI 0.5 vs 1.0.0 版本对比

### 4.1 核心差异一览表

| 维度 | Spring AI 0.5.x | Spring AI 1.0.0 | 是否破坏兼容 |
|------|------------------|------------------|------------|
| **ChatClient API** | `chatClient.call(prompt)` 返回 `ChatResponse` | 链式 API：`prompt().user().call().chatResponse()` | ✅ 是 |
| **流式 API** | `chatClient.stream(prompt)` 返回 `Flux<ChatResponse>` | `.stream().chatResponse()` 或 `.content()` | ✅ 是 |
| **Tool/Function Calling** | `@Tool` + `ToolCallbackProvider` | `@Tool` 保留，`ToolCallback` 接口重构 | ⚠️ 部分 |
| **RAG API** | `QuestionAnswerAdvisor` | 新增 `RetrievalAugmentationAdvisor` + `DocumentRetriever` | ✅ 是 |
| **VectorStore API** | `add()` / `similaritySearch()` | 新增 `SearchRequest` 对象 | ⚠️ 部分 |
| **ChatMemory API** | `ChatMemory` + `MessageWindowChatMemory` | 新增 `ChatMemoryRepository` 接口（可插拔） | ✅ 是 |
| **Advisor API** | `CallAroundAdvisor` / `StreamAroundAdvisor` | 统一重构（1.0.5 进一步变化） | ✅ 是 |
| **EmbeddingModel** | 直接注入 | 新增 `EmbeddingModelCustomizer` | ⚠️ 部分 |
| **MCP 支持** | 无 | 1.0.0 正式引入 `spring-ai-mcp` 模块 | ✅ 新增 |

### 4.2 ChatClient API 变化（面试高频）

```java
// === Spring AI 0.5.x 写法 ===
ChatResponse response = chatClient.call(
    new Prompt("你好", ChatOptions.builder().temperature(0.7).build())
);
Flux<ChatResponse> stream = chatClient.stream(prompt);

// === Spring AI 1.0.0+ 写法（你项目用的）===
ChatClient.CallResponseSpec spec = chatClient.prompt()
    .user("你好")
    .call();
ChatResponse response = spec.chatResponse();
String content = spec.content();  // 直接拿文本

// 流式
Flux<ChatResponse> stream = chatClient.prompt()
    .user("你好")
    .stream()
    .chatResponse();
```

### 4.3 RAG API 变化

```java
// === 0.5.x：QuestionAnswerAdvisor ===
// （你项目里 CustomRagAdvisor 是基于这个扩展的）
Advisor ragAdvisor = new QuestionAnswerAdvisor(
    vectorStore,
    SearchRequest.query(query).withTopK(3).withSimilarityThreshold(0.3)
);

// === 1.0.0+：RetrievalAugmentationAdvisor ===
// （更灵活的抽象，支持多路召回、重排序）
RetrievalAugmentationAdvisor ragAdvisor = RetrievalAugmentationAdvisor.builder()
    .documentRetriever(new VectorStoreDocumentRetriever(vectorStore,
        SearchRequest.query(query).topK(3).similarityThreshold(0.3)))
    .documentJoiner(new ConcatenationDocumentJoiner())
    .build();
```
