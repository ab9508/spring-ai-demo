### 上午（2小时）：RAG全链路口述训练

**任务：把以下链路默写出来，然后逐节讲清楚**

```
文档入库：上传 → Tika/PDF解析 → OverlappingTextSplitter分块 → nomic-embed-text向量化 → PgVector存储
检索链路：用户提问 → embedding → PgVector Top-K → 相对分数过滤 → 注入system/user prompt → LLM生成
```

**必须能回答的追问：**
- 为什么不用固定阈值？（分数飘，0.35~0.62都有）
- overlap为什么设10%？（防边界语义断裂）
- Top1<0.45和Top1-Top2<0.08分别防什么问题？
- Advisor的执行顺序怎么控制？（order值，先Memory后RAG）
- augmentSystemMessage()是追加还是替换？（追加）

**练习方式：** 对着空白纸，把RAG链路画出来，然后解释每一步"为什么这样做"

### 下午（2小时）：Redis ChatMemory + Tool Calling深挖

**任务A：Redis ChatMemory 3分钟口述**

默写以下4个点，每点一句话说清楚：
1. 为什么要自研？（1.0.x不支持Redis，Spring AI Alibaba版本冲突）
2. 数据结构怎么选？（Redis List，RPUSH追加，LRANGE读取）
3. 怎么防膨胀？（maxMessages=20 + TTL 24h + LTRIM裁剪）
4. JSON序列化怎么处理？（@JsonTypeInfo保留子类型信息）

**任务B：Tool Calling踩坑 2分钟口述**

必须能说清楚这个坑：
> "ChatClient.Builder是可变对象，defaultTools()修改自身。同一个Builder先build带工具的，再build无工具的，第二个也被污染。解决方案：每次用ChatClient.builder(chatModel)工厂方法创建全新Builder，完全隔离。"

**任务C：MCP踩坑 1分钟口述**
> "有Tomcat必须用webmvc版Starter，webflux版SSE路由在Tomcat下不注册→404。Client的url只填根地址，不加/sse后缀。"

## Day 2：拓展补课 · 框架对比 + 新技术

**目标：把LangChain/Dify/多平台对接、DeepSeek版本、模型投毒等"见过但没做过"的内容，整理成能说的话术**

### 上午（2小时）：LangChain / LlamaIndex 对比突击

**核心结论（背下来）：**

| 维度 | LangChain | LlamaIndex | Spring AI |
|------|-----------|------------|-----------|
| 语言 | Python/JS | Python | Java |
| 定位 | 通用AI链路 | 专精RAG/检索 | Java生态AI整合 |
| 核心抽象 | Chain/Agent/Tool/Memory | Index/Query Engine/Node | ChatClient/Advisor/Tool/VectorStore |
| 生态 | 最丰富（500+ integrations） | 中等 | 快速成长中 |
| 生产维护 | 版本变化快，Breaking Change多 | 一般 | Spring标准化，相对稳定 |

**LangChain核心概念速记（5个）：**
1. **Chain** = 顺序调用多个组件，对应Spring AI的Advisor链
2. **Agent** = LLM自主决策调用工具，对应@Tool + Tool Calling
3. **Memory** = 对话历史管理，对应ChatMemory
4. **Vector Store** = 向量数据库抽象，对应VectorStore接口
5. **Retriever** = 检索器，对应Spring AI的SearchRequest

**面试话术：**
> "LangChain的核心概念和Spring AI是一一对应的——Chain对应Advisor链，Agent对应Tool Calling，Memory对应ChatMemory，VectorStore接口都是统一抽象。我用Spring AI做的事情，换LangChain只是换API写法，核心设计思路完全一样。Spring AI的优势是原生Java生态，不需要Python微服务，事务、监控、配置中心直接复用Spring全家桶。"

### 晚上（1小时）：模型投毒 + AI安全 + 评估体系

**模型投毒三层防御（背结构）：**
```
1. 数据层：知识库入库审计 + 内容扫描 + 版本控制
2. Prompt层：输入消毒（检测注入模式）+ System Prompt加固 + 角色隔离
3. 输出层：敏感信息过滤 + 来源标注 + 低置信度触发人工兜底
```

**RAG评估指标（背6个）：**
- 检索命中率（Recall@K）
- 答案相关性
- 幻觉率
- TTFT（首Token延迟）
- 端到端延迟
- Token消耗/次

### 下午（1.5小时）：薄弱项专项补强

**排查这5个常见卡壳点：**

**卡壳点1：被问到Python怎么回答**
> "我的主力是Java，Spring AI在Java生态里的完整度已经很高了。Python我有基础，看得懂LangChain的代码，概念层面没有障碍。如果岗位需要Python，我的学习曲线会很短，因为AI应用开发的核心设计思路是相通的，不是语言本身的问题。"

**卡壳点2：被问到Fine-tuning怎么回答**
> "我目前的方向是Prompt工程和RAG，不依赖Fine-tuning——原因是Fine-tuning成本高、迭代慢、泛化性差，而RAG+结构化输出在大多数业务场景下已经够用，且可以随知识库更新实时生效。"

**卡壳点3：被问到系统设计中的Agent自进化**
> "Agent自进化的核心是数据飞轮：记录人类对AI建议的采纳/修改/拒绝行为，分析被拒绝的原因（工具选错/参数错误/理解偏差），针对性优化Prompt、工具描述、或RAG知识库，下一轮Agent性能提升，形成正向循环。"

**卡壳点4：被问到Milvus**
> "生产用的PgVector，Milvus了解架构（etcd+MinIO+Milvus三组件，HNSW/IVFFlat索引）。Spring AI的VectorStore接口是统一抽象，切换向量数据库只换一个Bean，业务代码不动。"

**卡壳点5：被问到你薪资预期**
> "期望税前25K，综合考虑技术方向匹配度和发展空间，有灵活性。"（或根据实际情况调整）
