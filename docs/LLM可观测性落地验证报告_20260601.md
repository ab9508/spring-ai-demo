# LLM可观测性落地验证报告

> 日期：2026-06-01 | 项目：spring-ai-demo | 版本：v1.0
> Chat模型：qwen2.5:3b (本地) | Embedding：bge-large-zh-v1.5

## 一、落地内容

通过 AOP 切面拦截所有 `ChatModel.call(Prompt)` 调用，自动记录每次 LLM 调用的完整链路，异步写入 PostgreSQL。

### 新增文件

| 文件 | 作用 |
|------|------|
| `entity/LLMCallLog.java` | 日志实体（13个字段） |
| `dao/LLMCallLogDao.java` | JdbcTemplate DAO（异步写入+按session/时间查询） |
| `aspect/LLMCallLoggerAspect.java` | AOP切面（含CGLIB去重） |
| `controller/AdminController.java` | 查询接口 `/admin/logs` |
| `pom.xml` | 添加 `spring-boot-starter-aop` |
| `init-data.sql` | 加 `llm_call_log` 建表DDL |
| `ChatClientConfig.java` | 添加 `logExecutor` 异步线程池 |
| `SpringAiDemoApplication.java` | 添加 `@EnableAsync` |

### 数据链路

```
用户请求 → ChatClient → [AOP拦截ChatModel.call()]
  ↓ 记录开始时间+提取Prompt
LLM执行（qwen2.5:3b）
  ↓ 记录响应+token+耗时
[@Async线程池] → 异步写入llm_call_log表
  ↓
管理员通过 /admin/logs 查询
```

### 日志记录字段

| 字段 | 示例值 |
|------|--------|
| question | "查一下订单ORD-001" |
| model | OllamaChatModel |
| token_input | 1632 |
| token_output | 48 |
| latency_ms | 21489 |
| cost | ¥0.00168 |

### 修复点

| 问题 | 修复 |
|------|------|
| CGLIB代理导致同一次调用记2次 | 新增 `ConcurrentHashMap` 去重：同一个Prompt对象在100ms内只记一次 |

## 三、已知限制

| 问题 | 说明 |
|------|------|
| 本地模型无token统计 | Ollama/Qwen本地模型不返回token用量，当前`token_input/output`为0；云API（DeepSeek）会正常返回 |
| 费用估算简化 | 当前按0.001元/1K tokens估算，不精确，仅用于参考 |
| 日志表需要手动建 | 不在Spring自动DDL范围内，需执行 `init-data.sql` 或手动CREATE TABLE |

## 四、使用方式

```bash
# 查最近日志
curl http://localhost:8080/admin/logs?limit=10

# 查某次会话的日志
curl http://localhost:8080/admin/logs/session?sessionId=xxx
```
