## 一、核心概念（面试能说就行）

### 1.1 Docker 是什么

**一句话**：把应用和它的运行环境打包成一个"容器"，在哪里都能跑。

```
传统方式：
  "在我电脑上能跑啊！" → 换台电脑就各种报错
  因为：JDK 版本不同、系统不同、配置不同...

Docker 方式：
  打包成容器 → 在任何装了 Docker 的机器上都能跑
  因为：容器里自带 JDK、配置、依赖，跟外部环境隔离
```

### 1.2 镜像 vs 容器

| 概念 | 类比 | 说明 |
|------|------|------|
| **镜像（Image）** | 安装包 / ISO 文件 | 只读的模板，包含运行所需的一切 |
| **容器（Container）** | 运行中的虚拟机 | 从镜像创建的实例，可以启动/停止/删除 |

```
镜像（PostgreSQL）──→ 创建 ──→ 容器1（运行中，端口5432）
                 └──→ 创建 ──→ 容器2（另一个数据库实例）
```

一个镜像可以创建多个容器（类似一个类可以 new 多个对象）。

### 1.3 docker run vs docker-compose

| 命令 | 用途 | 类比 |
|------|------|------|
| `docker run` | 启动**单个**容器 | 手动敲命令启动一个程序 |
| `docker-compose` | 启动**多个**容器（编排） | 用配置文件批量启动，还能定义依赖关系 |

**实际项目几乎都用 docker-compose**，因为：
- 一个应用通常需要多个组件（数据库 + 缓存 + 应用本身）
- docker-compose 一次启动全部，还能定义启动顺序

### 1.4 数据持久化（Volumes）

```
容器删除后，容器内的数据会丢失！

比如：你在容器里的 PostgreSQL 里建了表、插入了数据
      删除容器 → 数据全没了 ❌

解决方案：Volume（数据卷）
      把容器内的数据目录映射到宿主机（你的电脑）的某个目录
      容器删除了 → 宿主机上的数据还在 ✅
      重新创建容器 → 挂载同一个 Volume → 数据恢复 ✅
```

## 二、需要同事帮忙做的事

### 2.1 直接说的话术

> "我有个 Spring Boot 项目需要 PostgreSQL + pgvector 扩展，你帮我写个 docker-compose.yml 能跑起来就行，我用 Win11。"

### 2.2 你需要确认的关键点

| 问题 | 为什么问 | 理想回答 |
|------|----------|----------|
| 公司用 Docker Desktop 还是 Docker Engine？ | 影响操作方式 | Docker Desktop（Win11 友好） |
| 公司用的是 WSL2 后端吗？ | 影响路径映射 | 是（Win11 默认） |
| 有现成的 PostgreSQL 镜像吗？ | 不需要从零搭建 | 有内部镜像仓库更好 |
| 数据卷映射到宿主机的哪个目录？ | 知道数据存在哪 | D:/docker-data 或类似 |

### 2.3 你需要看懂的 docker-compose.yml

```yaml
version: '3.8'           # docker-compose 版本号，不用管

services:                 # 定义要启动的容器列表
  postgres:               # 容器名称（自定义）
    image: pgvector/pgvector:pg17    # 镜像（包含 pgvector 扩展的 PostgreSQL）
    container_name: ai-postgres      # 容器运行后的名称
    ports:
      - "5432:5432"       # 宿主机端口:容器端口
                          # 意思是：你电脑的 5432 端口 → 容器的 5432 端口
    environment:
      POSTGRES_USER: postgres       # 数据库用户名
      POSTGRES_PASSWORD: 123456     # 数据库密码
      POSTGRES_DB: ai_db            # 自动创建的数据库名
    volumes:
      - pgdata:/var/lib/postgresql/data   # 数据持久化
                                          # pgdata 是 volume 名称
                                          # /var/lib/postgresql/data 是 PG 的数据目录

volumes:                  # 声明数据卷
  pgdata:                 # 名字叫 pgdata，Docker 自动管理存储位置
```

**对照 Java 理解**：
- `services` → 你要启动的 Spring Boot 应用们
- `image` → 第三方 jar 依赖
- `ports` → application.yml 里的 server.port
- `environment` → application.yml 里的配置
- `volumes` → 数据库连接串里指定的数据目录

## 三、常用命令速查

```bash
# ===== 基础操作 =====

# 查看运行中的容器（类似 ps）
docker ps

# 查看所有容器（包括已停止的）
docker ps -a

# 启动 / 停止 / 重启容器
docker start ai-postgres
docker stop ai-postgres
docker restart ai-postgres

# 查看容器日志（类似 tail -f）
docker logs -f ai-postgres

# 删除容器（先 stop）
docker rm ai-postgres

# ===== docker-compose 操作 =====

# 启动所有容器（后台运行）
docker-compose up -d

# 停止所有容器
docker-compose down

# 停止并删除数据卷（⚠️ 数据会丢失！）
docker-compose down -v

# 查看容器状态
docker-compose ps

# ===== 进入容器内部 =====

# 以 postgres 用户身份进入 PostgreSQL 容器
docker exec -it ai-postgres psql -U postgres -d ai_db

# 进入容器的 bash
docker exec -it ai-postgres bash
```

## 四、验证 pgvector 可用的 SQL

进入容器后，执行以下 SQL 验证 pgvector 已安装：

```sql
-- 1. 启用向量扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 2. 验证扩展已启用
SELECT * FROM pg_extension WHERE extname = 'vector';

-- 3. 测试向量操作
-- 创建带向量列的表
CREATE TABLE test_vectors (
    id SERIAL PRIMARY KEY,
    content TEXT,
    embedding vector(768)     -- 768维向量
);

-- 插入测试数据
INSERT INTO test_vectors (content, embedding)
VALUES ('测试文本', array_fill(0, ARRAY[768]));

-- 查询验证
SELECT id, content, dim(embedding) FROM test_vectors;

-- 清理
DROP TABLE test_vectors;
```

如果上面全部执行成功，说明 pgvector 可用 ✅

## 五、与 Java 开发的关联

```
你之前接触过的类似概念：

Docker Image     ≈ Maven 依赖（从远程仓库下载）
Docker Container ≈ JVM 进程（运行中的实例）
docker-compose   ≈ Spring Boot 多模块启动脚本
Volume           ≈ MySQL 的 datadir（数据存储位置）
ports 映射       ≈ application.yml 的 server.port
environment      ≈ application.yml 的配置项

你现在不需要学会写 Dockerfile（那是运维的事），
只需要学会：
1. 看懂 docker-compose.yml
2. docker-compose up -d 启动
3. docker-compose down 停止
4. docker logs 看日志
5. docker exec 进入容器执行命令
```
