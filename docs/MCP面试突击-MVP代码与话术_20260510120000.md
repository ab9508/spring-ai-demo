## 一、为什么要学MCP（面试价值定位）

**MCP本身对单机项目没有额外收益**，它的价值在于：

| 场景 | 用Tool Calling | 用MCP |
|------|---------------|-------|
| 单个Spring Boot应用 | 够用，@Tool方法直接调 | 过度设计 |
| 多个AI应用共享同一套工具 | 每个应用都要复制@Tool代码 | 工具服务化，部署一次共享 |
| 工具需要独立扩缩容 | 无法单独部署 | Tool Server独立部署 |
| 非Java工具（Python脚本/Node服务） | 需要JNI或HTTP包装 | 直接实现MCP Server协议 |

**面试定位**：你的项目用的是Tool Calling（@Tool），MCP是你了解的**下一层标准化架构**。说出来体现你有架构视野，不只是会写业务代码。

## 二、MCP vs Tool Calling 一句话区别

```
Tool Calling = 同进程直接调Java方法（@Tool注解 → LLM → 反射调用）
MCP         = 跨进程JSON-RPC调用（标准协议 → 任意语言实现工具服务）
```

**底层HTTP请求的区别：**

```
# Tool Calling：请求体含tools字段，LLM返回tool_calls，本地反射执行
POST https://api.deepseek.com/v1/chat/completions
{ "tools": [{"name":"queryOrder","description":"..."}], ... }

# MCP：流程一样，只是工具执行时走JSON-RPC转发到远程Server
# LLM层看不出区别，区别在执行层
```

## 三、最小MVP代码（4个文件看懂架构）

> 这4个文件是spring-ai-demo项目里的实际代码，面试时能说出每个文件的作用。

### 3.1 工具定义（Server侧，两者共用）

```java
// com/example/ai/tool/OrderTools.java
// ✅ 这个@Tool方法同时支持Tool Calling和MCP Server
// Tool Calling：直接被ChatClient.defaultTools()引用
// MCP Server：被Starter自动扫描，通过SSE暴露给外部Client
@Component
public class OrderTools {

    @Tool(description = "根据订单号查询订单状态和物流信息")
    public String queryOrder(String orderId) {
        // 模拟查询，实际对接数据库
        return String.format("订单%s：已发货，预计明天到达", orderId);
    }
}
```

**关键点**：@Tool方法无需改动，Server/Client是**配置层**的事，和业务代码解耦。

---

### 3.2 MCP Server配置（application-mcp-server.yml）

```yaml
server:
  port: 8081

spring:
  ai:
    mcp:
      server:
        enabled: true
        name: spring-ai-demo-mcp-server
        version: 1.0.0
        # SSE订阅端点默认 /sse，Client连这里
        # 消息端点默认 /mcp/message，底层自动处理
```

**启动命令**：
```
mvn spring-boot:run -Dspring-boot.run.profiles=mcp-server
```

**Server启动后暴露两个端点**：
- `GET /sse` — Client来建立SSE长连接（订阅事件）
- `POST /mcp/message` — Client发JSON-RPC消息

---

### 3.3 MCP Client配置（application-mcp-client.yml）

```yaml
server:
  port: 8082

spring:
  ai:
    mcp:
      client:
        sse:
          connections:
            default:
              url: http://localhost:8081   # 只填根URL！不要加/sse或/mcp/message
              # Client自动访问 url + /sse 建立连接
```

**踩坑**：`url`只填端口，不要写成 `http://localhost:8081/mcp/message`（这是message端点，不是SSE订阅端点）。

---

### 3.4 MCP Client控制器

```java
// com/example/ai/controller/McpClientController.java
@RestController
@RequestMapping("/mcp")
@ConditionalOnProperty(name = "app.mcp.client.enabled", havingValue = "true")
public class McpClientController {

    private final ChatClient chatClient;

    // ToolCallbackProvider由MCP Client Starter自动装配：
    // 启动时连Server → 获取工具列表 → 封装为ToolCallbackProvider
    public McpClientController(ChatClient.Builder builder,
                               ToolCallbackProvider mcpTools) {
        this.chatClient = builder
                .defaultTools(mcpTools)   // 注入远程工具，用法和Tool Calling完全一样
                .build();
    }

    @GetMapping("/chat")
    public String chat(@RequestParam String msg) {
        return chatClient.prompt(msg).call().content();
    }
}
```

**核心**：`ToolCallbackProvider` 是MCP Starter注入的远程工具代理，对ChatClient来说和本地@Tool没有区别。

## 四、面试话术（30秒/2分钟两个版本）

### 30秒版（面试官问"你了解MCP吗"）

> "了解。MCP是Anthropic开源的工具调用标准协议，解决的是多AI应用共享工具的问题。  
> 我项目里用的是Spring AI的Tool Calling，@Tool注解直接在同进程里调用。  
> MCP是在这个基础上加了一个标准化的跨进程调用层，工具服务可以独立部署，多个AI应用共享，类似微服务的思路。  
> Spring AI 1.0.5提供了MCP Server/Client的Starter，@Tool方法无需修改就能通过SSE暴露成MCP工具。"

### 2分钟版（面试官追问"能详细说说吗"）

> "MCP的架构分三层：Host、Client、Server。  
>
> Host就是你的AI应用，比如我的Spring Boot项目。  
> MCP Client由Spring AI Starter自动创建，负责连接远程Server、拉取工具列表。  
> MCP Server是工具提供方，把@Tool方法通过SSE协议暴露出来。  
>
> 通信用JSON-RPC 2.0，传输层用SSE（Server-Sent Events）。  
> Client启动时先发 `initialize` 握手，再发 `tools/list` 拉工具清单，  
> LLM决定调用工具时，Client发 `tools/call` 请求给Server，Server执行后返回结果。  
>
> 和Tool Calling的区别：  
> Tool Calling是同进程调用，@Tool方法在同一个JVM里；  
> MCP是跨进程调用，工具在另一个服务里，通过JSON-RPC传输。  
> 对LLM和ChatClient来说，两者用法完全一样，区别只在执行层。  
>
> 我在项目里搭了一个单模块同时支持Server和Client的Demo，  
> 通过Spring Profile切换（mcp-server/mcp-client），验证了整个调用链路。"

## 五、高频追问与回答

**Q：MCP和OpenAI的Function Calling有什么关系？**  
A：Function Calling是OpenAI协议里LLM侧的能力（LLM决定调哪个函数、返回tool_calls字段）。MCP是工具执行层的标准，解决"工具怎么部署和对接"的问题。两者是不同层次，MCP依赖Function Calling来触发工具调用。

**Q：MCP的SSE和WebSocket有什么区别？**  
A：SSE是单向推送（Server→Client），HTTP长连接，实现简单，适合事件通知。WebSocket是全双工，实现复杂。MCP选SSE是因为工具调用的场景是"Server推结果给Client"，单向够用，没必要引入WebSocket的复杂度。MCP 2025年也新增了Streamable HTTP传输方式，更灵活。

**Q：为什么不直接用HTTP REST而要用SSE+JSON-RPC？**  
A：SSE支持Server主动推送，工具执行是异步的，执行完才推结果，比轮询高效。JSON-RPC 2.0提供了标准的请求/响应/错误格式，有requestId可以匹配异步响应，REST的RESTful语义不适合这种RPC调用模式。

**Q：Spring AI的MCP Starter做了什么？**  
A：Server侧：自动扫描@Tool注解方法，注册为MCP工具，创建SSE端点（/sse）和消息端点（/mcp/message）。Client侧：读取yml里的Server地址，建立SSE连接，拉取工具列表，封装为ToolCallbackProvider Bean，自动注入到Spring容器。

**Q：生产环境MCP Server如何保证安全？**  
A：加认证（Bearer Token或OAuth2），在SSE连接建立时校验；工具方法加权限控制；Server不直连数据库，走内部RPC。（诚实说：我Demo里没做认证，只是验证了调用链路）

## 六、踩坑速记（避免面试露馅）

| 坑 | 正确认知 |
|----|---------|
| Client的url写成 `http://host:8081/sse` | url只填根地址，Client自动拼/sse |
| 以为MCP Server自动暴露/mcp/message给Client直连 | /mcp/message是消息端点，/sse才是Client建立连接的端点 |
| MCP Client启动超时 | 必须先启Server，Client启动时就会去连Server |
| 以为@Tool方法要改造才能用MCP | 不用改，Starter自动扫描，@Tool方法对Server/Client透明 |
| spring-ai-starter-mcp-server-webflux和webmvc的区别 | webflux用响应式SSE推送，webmvc用传统Servlet。选哪个看你的项目是不是WebFlux响应式栈 |
