## 一、依赖配置类问题

### 坑1：Spring AI 依赖放错位置——dependencyManagement vs dependencies

**现象**：代码里 import 的类全部报红，`PagePdfDocumentReader`、`SimpleVectorStore` 找不到

**原因**：把依赖放到了 `<dependencyManagement>` 里，这个标签只声明版本不实际引入 jar

**解决**：移到 `<dependencies>` 里，版本由 BOM 统一管理

```xml
<!-- ❌ 错误：只声明版本，不会下载 jar -->
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-pdf-document-reader</artifactId>
        </dependency>
    </dependencies>
</dependencyManagement>

<!-- ✅ 正确：实际引入依赖 -->
<dependencies>
    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-pdf-document-reader</artifactId>
        <!-- 版本由 spring-ai-bom 管理，不需要写 version -->
    </dependency>
</dependencies>
```

**后续避免**：记住一个口诀——`dependencyManagement` 是"菜单"（只有菜名和价格），`dependencies` 是"下单"（真正上菜）

---

### 坑2：SimpleVectorStore 不存在 starter

**现象**：`spring-ai-starter-vector-store-simple` 在 BOM 和 Maven Central 都找不到

**原因**：Spring AI 的 `SimpleVectorStore` 是内存级实现，官方认为不需要自动配置，所以没有提供 starter

**解决**：引入核心模块 `spring-ai-vector-store`，在启动类手动创建 `@Bean`

```xml
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-vector-store</artifactId>
</dependency>
```

```java
@Bean
public VectorStore vectorStore(EmbeddingModel embeddingModel) {
    return SimpleVectorStore.builder(embeddingModel).build();
}
```

**后续避免**：遇到 "starter 不存在" 时，去 BOM 里找同名核心模块（去掉 `-starter`），大概率是手动 @Bean 模式

### 坑3：Ollama starter 导致双 ChatModel 冲突

**现象**：启动报错 `ChatClientAutoConfiguration required a single bean, but 2 were found: ollamaChatModel, openAiChatModel`

**原因**：引入了 `spring-ai-starter-model-ollama`，它的 `OllamaChatAutoConfiguration` 自动配置了 `OllamaChatModel`，与已有的 `OpenAiChatModel`（DeepSeek）冲突。我只想用 Ollama 做 Embedding，不需要它的 Chat 能力

**解决**：不用 starter，用纯核心 jar `spring-ai-ollama`，手动创建 Bean，不触发 Chat 自动配置

```xml
<!-- ❌ 会自动配置 OllamaChatModel，和 DeepSeek 冲突 -->
<artifactId>spring-ai-starter-model-ollama</artifactId>

<!-- ✅ 纯核心 jar，需要什么就手动创建什么 Bean -->
<artifactId>spring-ai-ollama</artifactId>
```

**后续避免**：当项目需要同时对接多个模型供应商（如 Chat 用 A、Embedding 用 B），不要同时引入两个 starter。至少有一个用核心 jar + 手动 @Bean

---

### 坑4：OllamaEmbeddingModel 构造函数参数全部不能为 null

**现象**：编译通过但启动报错 `observationRegistry must not be null`，改了之后又报 `modelManagementOptions must not be null`

**原因**：Spring AI 1.0.5 的 `OllamaEmbeddingModel` 4 参数构造函数内部有 `Assert.notNull` 校验，全部不接受 null

**解决**：
```java
new OllamaEmbeddingModel(
    ollamaApi,
    OllamaOptions.builder().model("nomic-embed-text").build(),
    ObservationRegistry.NOOP,                        // 空实现，不是 null
    ModelManagementOptions.builder().build()          // 空配置，不是 null
);
```

**后续避免**：Spring AI 的构造函数倾向于不可变设计，参数宁可给空实现也不要给 null

## 二、API 调用类问题

### 坑5：OpenAI 兼容协议的 Embedding 路径拼接 404

**现象**：调用智谱 AI Embedding 时报 404，日志显示请求路径只有 `/v1/embeddings`，没有域名前缀

**原因**：`OpenAiApi` 的 `embeddingsPath` 默认值是 `/v1/embeddings`（以 `/` 开头）。Spring `RestClient.uri()` 方法对**以 `/` 开头的路径视为绝对路径**，会**忽略 baseUrl**。

```
baseUrl        = https://open.bigmodel.cn/api/paas/v4
embeddingsPath = /v1/embeddings          ← 以 / 开头，绝对路径！

RestClient 实际请求: /v1/embeddings       ← baseUrl 被忽略了！❌
```

**解决**：把 `embeddingsPath` 改为不以 `/` 开头的相对路径

```
baseUrl        = https://open.bigmodel.cn/api/paas/v4
embeddingsPath = embeddings               ← 相对路径

RestClient 实际请求: https://open.bigmodel.cn/api/paas/v4/embeddings  ✅
```

**后续避免**：使用 Spring RestClient 时，路径参数一律不以 `/` 开头，除非确实要忽略 baseUrl

## 三、面试题包装

### 面试题："你在 Spring AI 项目开发中遇到了哪些技术问题？"

**回答模板**（根据时间控制详细程度）：

> 在做 Spring AI 的 RAG（检索增强生成）功能时，我遇到了三类问题：
>
> **第一类是依赖管理问题。** Spring AI 的 BOM 中，`SimpleVectorStore` 没有提供 starter，需要手动引入核心模块并创建 Bean。更棘手的是，当我同时引入 OpenAI starter（用于对接 DeepSeek）和 Ollama starter（用于本地 Embedding）时，两个 starter 都自动配置了 `ChatModel` Bean，导致 Spring 容器不知道该注入哪个。我最终的方案是 Ollama 只用核心 jar 而不用 starter，手动创建 `OllamaEmbeddingModel` Bean，这样就不会触发 Ollama Chat 的自动配置。
>
> **第二类是 API 兼容性问题。** 智谱 AI 用 OpenAI 兼容协议，但 Embedding 的请求路径拼接有问题。排查发现 `OpenAiApi` 的 `embeddingsPath` 默认以 `/` 开头，Spring 的 `RestClient` 会把它当作绝对路径，忽略掉 `baseUrl`，导致请求 404。改成相对路径就好了。这个问题是通过读源码定位的。
>
> **第三类是构造函数参数问题。** `OllamaEmbeddingModel` 的构造函数有 4 个参数，其中 `ObservationRegistry` 和 `ModelManagementOptions` 都不允许传 null。Spring AI 在这里用了 `Assert.notNull` 做防御性校验，必须传空实现而不是 null。
>
> 总体感受是，Spring AI 还在快速迭代中（GA 版才 1.0.x），API 变化大、文档有时跟不上版本，遇到问题最好直接看源码。

### 面试题："RAG 的问答结果不够准确，你怎么排查和优化？"

**回答模板**：

> RAG 不准确一般有四个优化方向，我按优先级排序：
>
> **1. 文本切分（最关键）**：默认的 `TokenTextSplitter` chunk size 是 800 Token，overlap 是 0。overlap 为 0 会导致关键信息被截断在两个 chunk 之间。改成 200-300 的 overlap 能显著改善上下文完整性。
>
> **2. 检索参数**：默认 topK=5 没有相似度阈值，会把不相关的片段也传给模型，造成干扰。加上相似度阈值（比如 0.7 以上）能过滤掉噪音。
>
> **3. System Prompt**：让模型明确知道"只基于参考资料回答"，并且给出回答格式要求，比如"如果资料不足请说明"。
>
> **4. Embedding 模型**：nomic-embed-text 是轻量级模型，如果精度不够可以换 text-embedding-3-small 等更大的模型，代价是延迟和成本。

## 四、PgVector 切换相关问题（2026-04-28 补充）

### 坑7：PgVectorStoreAutoConfiguration 注入歧义——required a single bean, but 2 were found

**报错信息**：
```
Parameter 1 of method vectorStore in PgVectorStoreAutoConfiguration
required a single bean, but 2 were found:
    - ollamaEmbeddingModel
    - openAiEmbeddingModel
```

**根因**：
- `spring-ai-starter-model-openai` 包含 `OpenAiEmbeddingAutoConfiguration`，它会自动注册 `OpenAiEmbeddingModel`
- 即使在 `@SpringBootApplication(exclude = {OpenAiEmbeddingAutoConfiguration.class})` 中排除，1.0.5 版本下有时仍会注册
- `PgVectorStoreAutoConfiguration` 自动装配时需要注入唯一的 `EmbeddingModel`，找到两个就报错

**解决方案**：给手动定义的 `ollamaEmbeddingModel()` 加 `@Primary` 注解

```java
@Primary   // 有多个 EmbeddingModel 时，PgVectorStore 自动配置优先用这个
@Bean
public OllamaEmbeddingModel ollamaEmbeddingModel() { ... }
```

**面试价值**：体现了对 Spring 自动配置歧义解决机制的理解（`@Primary` vs `@Qualifier`）

---

### 坑8：pgvector 扩展未启用——"type vector does not exist"

**根因**：`initialize-schema: true` 只能自动建表，不能自动安装 PostgreSQL 扩展

**解决方案**：先在数据库手动执行
```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

## 五、Tool Calling 相关问题（2026-04-28 补充）

### 坑9：Spring AI 1.0.x Tool Calling API 重大变更——旧写法 @Bean+@Description+Function 已废弃

**报错信息**：
```
Failed to instantiate [AgentController]: Constructor threw exception
No @Tool annotated methods found in queryOrder.
Did you mean to pass a ToolCallback or ToolCallbackProvider?
If so, you have to use .toolCallbacks() instead of .tool()
```

**根因**：Spring AI 1.0.x 彻底废弃了 0.x 时代的 Function Bean 工具写法。

| 维度 | 旧写法（0.x / 教程常见）| 新写法（1.0.x 标准）|
|------|------------------------|---------------------|
| 类注解 | `@Configuration` | `@Component` |
| 方法声明 | `@Bean @Description("...") public Function<Req, Resp> toolName()` | `@Tool(description = "...") public Resp toolName(参数)` |
| 注册工具 | `chatClientBuilder.defaultTools("beanName")` | `chatClientBuilder.defaultTools(toolInstance)` |
| 参数方式 | 必须包装成 Request record/class | 直接写方法参数 |

**解决方案**：

```java
// 旧写法（删掉）
@Configuration
public class OrderTools {
    @Bean
    @Description("根据订单号查询...")
    public Function<OrderQueryRequest, OrderQueryResponse> queryOrder() {
        return request -> { ... };
    }
}

// 新写法（1.0.x）
@Component
public class OrderTools {
    @Tool(description = "根据订单号查询订单的当前状态、收货地址、物流信息。当用户询问订单状态时调用。")
    public OrderQueryResponse queryOrder(String orderId) {
        // 直接写逻辑
    }
}
```

```java
// Controller 注入方式同步修改
// 旧：chatClientBuilder.defaultTools("queryOrder")
// 新：
public AgentController(ChatClient.Builder chatClientBuilder, OrderTools orderTools) {
    this.chatClient = chatClientBuilder
            .defaultTools(orderTools)   // 传实例，Spring AI 自动扫描其 @Tool 方法
            .build();
}
```

**面试价值**：Spring AI 1.0.x 是 GA 版，这个 API 变化是求职中可以主动提到的技术认知点——"从 Function Bean 迁移到 @Tool 注解方法"。

## 六、待优化项备忘（未完成）

### TODO-1：文本切分参数调整（影响 RAG 回答质量）

**现状**：`TokenTextSplitter` 使用默认参数，回答效果不佳。

**默认参数值**（TokenTextSplitter 源码）：
```java
// 每段最大 Token 数
private static final int DEFAULT_CHUNK_SIZE = 800;
// 段与段之间的重叠 Token 数（保持上下文连贯）
private static final int DEFAULT_MIN_CHUNK_SIZE_CHARS = 350;
// 段结束时尽量在句号/换行处截断，保留最多这么多字符往前找
private static final int DEFAULT_MIN_CHUNK_LENGTH_TO_EMBED = 5;
// 每份文档最多切几段（0 = 不限制）
private static final int DEFAULT_MAX_NUM_CHUNKS = 10000;
```

**为什么默认参数效果不好**：
- `DEFAULT_CHUNK_SIZE=800 Token` 约等于 400-600 汉字，段落太长→检索的片段含太多噪音→AI回答不准
- 重叠 Token 不够→相邻段落之间的内容容易丢失
- 没有针对中文文档调优

**待优化方向**（下次实践）：
```java
// 参考调优值（中文 PDF 场景）
TokenTextSplitter splitter = new TokenTextSplitter(
    300,    // chunkSize：每段约150-200字，粒度更细
    50,     // minChunkSizeChars
    5,      // minChunkLengthToEmbed
    10000,  // maxNumChunks
    true    // keepSeparator
);
```

**其他优化方向**：
- `topK` 从默认 4 调到 5-8，多召回几段
- `similarityThreshold` 设置相似度阈值（如 0.7），过滤噪音片段
- System Prompt 中明确告知 AI "如果找不到答案直接说不知道"
