## 一、MCP是什么（30秒说清）

**MCP = Model Context Protocol（模型上下文协议）**

一句话：**MCP 是 Anthropic（Claude母公司）开源的标准协议，让大模型能以统一方式连接外部数据源和工具。**

类比：MCP 对 AI 应用 ≈ USB-C 对电子设备。以前每个工具都要单独对接（USB-A/Micro-USB/Lightning），MCP 统一了接口标准。

- 发布时间：2024年11月
- 发布方：Anthropic
- 状态：开源，已获得 OpenAI、Google、微软等主流厂商支持
- 协议规范：[modelcontextprotocol.io](https://modelcontextprotocol.io)

## 二、为什么需要MCP（解决什么问题）

### 没有 MCP 之前的痛点

```
每个AI应用都要单独对接每个工具：
┌──────────┐     ┌──────────┐
│ Claude   │────▶│ 自定义API │  ← 每个模型写一套对接代码
│ GPT      │────▶│ 自定义API │
│ 文心一言   │────▶│ 自定义API │
│ 通义千问   │────▶│ 自定义API │
└──────────┘     └──────────┘
重复劳动，N个模型 × M个工具 = N×M 套对接代码
```

### 有 MCP 之后

```
┌──────────┐     ┌──────────┐
│ Claude   │────▶│          │
│ GPT      │────▶│ MCP协议   │────▶ 工具/数据源
│ 文心一言   │────▶│（统一接口）│
│ 通义千问   │────▶│          │
└──────────┘     └──────────┘
N个模型 + M个工具 = N + M 套对接代码
```

**核心价值：一次开发，处处可用。**

## 三、核心架构（Host-Client-Server）

### 架构图

```
┌──────────────────────────────────────────────┐
│                 Host（宿主应用）                 │
│   如：Claude Desktop / IDE / 你的Spring Boot应用  │
│                                               │
│   ┌──────────┐  ┌──────────┐  ┌──────────┐    │
│   │ Client 1 │  │ Client 2 │  │ Client 3 │    │
│   │(连接DB)   │  │(连接文件)  │  │(连接API)  │    │
│   └────┬─────┘  └────┬─────┘  └────┬─────┘    │
└────────┼─────────────┼─────────────┼───────────┘
         │ 1:1         │ 1:1         │ 1:1
         ▼             ▼             ▼
   ┌──────────┐  ┌──────────┐  ┌──────────┐
   │ Server 1 │  │ Server 2 │  │ Server 3 │
   │ 数据库服务 │  │ 文件系统   │  │ 外部API   │
   └──────────┘  └──────────┘  └──────────┘
```

### 三个角色

| 角色 | 是什么 | 职责 |
|------|--------|------|
| **Host** | 运行LLM的应用 | 管理多个Client，协调交互（如Claude Desktop） |
| **Client** | 协议客户端 | 与单个Server保持1:1长连接，发送请求/接收响应 |
| **Server** | 能力提供方 | 暴露Tools/Resources/Prompts给Client调用 |

**关键约束：Client和Server是1:1关系，一个Client只连接一个Server。**

## 四、三大原语（Tools / Resources / Prompts）

### 一张表说清区别

| 维度 | Tools（工具） | Resources（资源） | Prompts（提示模板） |
|------|-------------|-----------------|-------------------|
| **本质** | 可执行函数 | 只读数据 | 复用模板 |
| **谁来触发** | **LLM自主决定** | 应用/客户端注入 | 用户主动调用 |
| **交互方向** | AI → 外部系统 | 外部数据 → AI | 用户 → AI |
| **有副作用** | ✅ 有（写文件、调API） | ❌ 只读 | ❌ 无 |
| **类比** | Java方法调用 | 读配置文件 | MyBatis #{} 模板 |

### 详细说明

#### Tools（工具）—— 和你简历里的Tool Calling最接近

LLM自主决定调用，类似你Spring AI项目里的 `@Tool` 注解方法。

```
用户："帮我查一下北京天气"
  → LLM分析意图，决定调用 getWeather("北京")
  → Server执行函数，返回结果
  → LLM基于结果生成自然语言回复
```

#### Resources（资源）—— 给LLM注入上下文

客户端主动把数据塞给LLM，类似RAG的检索结果注入。

```
应用把本地 todo.md 文件内容注入给LLM
  → LLM基于文件内容回答用户问题
  → 类比：CustomRagAdvisor把PgVector检索结果注入prompt
```

#### Prompts（提示模板）—— 预设对话模板

用户选择模板，LLM按模板格式回复。

```
用户选择 "/explain-code" 模板
  → 套用预设提示词："请逐行解释以下代码..."
  → LLM按模板格式输出
```

## 五、通信协议（JSON-RPC + SSE）

### 传输层

| 传输方式 | 适用场景 | 说明 |
|---------|---------|------|
| **stdio** | 本地CLI/桌面工具 | 进程间通信，Claude Desktop用的就是这个 |
| **SSE（HTTP）** | Web服务 | Server-Sent Events，Spring Boot推荐用这个 |
| **Streamable HTTP** | 2025-03新规范 | SSE的升级版，支持HTTP/2，生产推荐 |

### 消息格式：JSON-RPC 2.0

```json
// 1. 客户端请求
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/list",
  "params": {}
}

// 2. 服务端响应
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "tools": [
      {
        "name": "getWeather",
        "description": "获取城市天气预报",
        "inputSchema": {
          "type": "object",
          "properties": {
            "city": { "type": "string", "description": "城市名" }
          },
          "required": ["city"]
        }
      }
    ]
  }
}
```

### 连接生命周期

```
1. initialize     → 客户端发能力声明 + 协议版本
2. initialized    → 服务端确认，连接建立
3. 正常通信       → tools/list, resources/read, prompts/get ...
4. 关闭连接       → 任意一方断开
```

## 六、MCP vs Tool Calling（面试必问）

### 核心区别

| 维度 | Tool Calling | MCP |
|------|-------------|-----|
| **是什么** | 单个模型的能力（OpenAI/DeepSeek协议） | 跨模型的行业标准协议 |
| **协议归属** | 各模型厂商自定义 | Anthropic开源，社区标准 |
| **传输** | HTTP请求体内嵌tools字段 | JSON-RPC + SSE独立长连接 |
| **工具发现** | 代码写死在ChatClient里 | 运行时动态发现（tools/list） |
| **跨模型** | 换模型要重写对接 | 换模型零改动 |
| **工具复用** | 每个应用重复实现 | 一个Server服务多个Client |

### 用Java类比理解

```
Tool Calling ≈ 直接写JDBC（每个数据库写一套连接代码）
MCP          ≈ 用MyBatis（统一接口，换数据库只改配置）
```

### 和你项目的对应关系

| 你的Spring AI项目 | MCP等价物 |
|------------------|-----------|
| `@Tool` 注解方法 | MCP Server的Tool |
| `ChatClient.defaultTools()` | MCP Client动态获取Tool列表 |
| DeepSeek/OpenAI的tools协议 | MCP的JSON-RPC协议 |
| CustomRagAdvisor注入检索结果 | MCP的Resource（上下文注入） |

## 七、Spring AI 集成 MCP（代码实战）

### 环境要求

| 组件 | 版本 |
|------|------|
| JDK | 17+ |
| Spring Boot | 3.4.x |
| Spring AI | 1.0.5+ |
| 注意 | Spring AI 1.0.0-M6是最早期版本，生产用1.0.5 |

### Maven依赖

```xml
<!-- MCP Server（暴露工具给外部调用） -->
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-mcp-server-webflux</artifactId>
</dependency>

<!-- MCP Client（调用外部MCP服务） -->
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-mcp-client-webflux</artifactId>
</dependency>
```

### MCP Server 端（暴露工具）

```java
// 1. 定义工具方法（和你现有的@Tool写法一样）
@Component
public class OrderTool {

    @Tool(description = "根据订单号查询订单信息")
    public String queryOrder(@ToolParam(description = "订单号") String orderId) {
        // 查数据库返回订单信息
        return "订单号: " + orderId + ", 状态: 已发货";
    }
}

// 2. 注册为MCP工具
@Configuration
public class McpServerConfig {

    @Bean
    public ToolCallbackProvider mcpTools(OrderTool orderTool) {
        return ToolCallbackProvider.from(ToolCallbacks.from(orderTool));
    }
}
```

### 配置文件

```yaml
# MCP Server 配置
spring:
  ai:
    mcp:
      server:
        enabled: true
        name: ai-mcp-server
        version: 1.0.0
        type: SYNC                    # SYNC或ASYNC
        sse-message-endpoint: /mcp/message  # SSE端点
```

### MCP Client 端（调用工具）

```yaml
# MCP Client 配置
spring:
  ai:
    mcp:
      client:
        enabled: true
        sse:
          connections:
            order-service:
              url: http://localhost:8081/mcp/message
```

```java
@RestController
public class McpClientController {

    private final ChatClient chatClient;

    // ToolCallbackProvider会自动注入MCP Client发现的远程工具
    public McpClientController(
            ChatClient.Builder builder,
            ToolCallbackProvider mcpTools) {
        this.chatClient = builder.defaultTools(mcpTools).build();
    }

    @GetMapping("/chat")
    public String chat(@RequestParam String msg) {
        return chatClient.prompt(msg).call().content();
    }
}
```

### 核心流程

```
1. MCP Client启动 → 连接Server SSE端点
2. 发送 tools/list → Server返回可用工具列表（queryOrder等）
3. 用户发送"查一下订单ORD001"
4. ChatClient把远程MCP工具和本地提示词一起发给LLM
5. LLM决定调用 queryOrder("ORD001")
6. MCP Client通过JSON-RPC调用Server
7. Server执行方法返回结果
8. LLM基于结果生成自然语言回复
```

## 八、代码实战：在spring-ai-demo中搭建MCP

> 代码已集成到 spring-ai-demo 项目中，通过 Spring Profile 切换 Server/Client 模式

### 新增文件清单

```
spring-ai-demo/
├── pom.xml                                    # 新增 MCP Server + Client 依赖
├── src/main/java/com/example/ai/
│   ├── config/
│   │   └── McpServerConfig.java              # 【新增】MCP Server配置
│   └── controller/
│       └── McpClientController.java          # 【新增】MCP Client测试接口
└── src/main/resources/
    ├── application-mcp-server.yml            # 【新增】Server配置（8081端口）
    └── application-mcp-client.yml            # 【新增】Client配置（8082端口）
```

### 核心设计

**MCP Server（复用现有 @Tool）**：
- `McpServerConfig` 通过 `@ConditionalOnProperty` 按 profile 激活
- `ToolCallbacks.from(orderTools)` 把现有的 `@Tool` 方法转为 MCP 工具
- 无需重写任何工具代码，和 Tool Calling 共用同一套 `OrderTools`

**MCP Client（远程调用）**：
- `application-mcp-client.yml` 配置 Server 的 SSE 地址
- Spring AI 自动装配 `ToolCallbackProvider`，启动时连接 Server 获取工具列表
- `McpClientController` 注入的 ChatClient 自动携带远程工具能力

### 启动步骤

```bash
# 前提：Ollama 运行中（11434端口）+ PostgreSQL 运行中（5432端口）

# 步骤1：启动 MCP Server（8081端口）
cd spring-ai-demo
mvn spring-boot:run -Dspring-boot.run.profiles=mcp-server

# 步骤2：新开终端，启动 MCP Client（8082端口）
mvn spring-boot:run -Dspring-boot.run.profiles=mcp-client

# 步骤3：测试 MCP Client 调用远程工具
curl "http://localhost:8082/mcp/chat?msg=查一下订单ORD001的物流"
```

### 验证要点

1. **Server启动日志**：看到 `【MCP Server】注册了 3 个MCP工具` 说明工具暴露成功
2. **Client启动日志**：看到 SSE 连接成功 + `【MCP Client】ChatClient 已注入MCP远程工具`
3. **调用验证**：Client发消息后，LLM会自动决定调用Server端的 queryOrder 工具
4. **关键区别**：Client进程里没有 OrderDao/数据库连接，工具调用完全通过JSON-RPC转发到Server端执行

## 九、面试高频问题

### Q1："MCP和Tool Calling有什么区别？"
> Tool Calling是单个模型厂商的实现（如OpenAI的function calling），MCP是跨模型的标准协议。Tool Calling把工具定义写死在HTTP请求里，MCP通过独立长连接动态发现工具。类比：Tool Calling是直连数据库，MCP是统一数据访问层。

### Q2："你项目里用了MCP吗？"
> 目前项目直接用了Spring AI的Tool Calling（@Tool注解），本质上是模型级别的工具调用。MCP是在此之上的协议标准化层。我了解MCP协议规范，理解它的Client-Server架构和三大原语，知道Spring AI已经提供了MCP的Starter支持。

### Q3："MCP的三大原语是什么？"
> Tools、Resources、Prompts。Tools是LLM可调用的函数，类似我项目里的@Tool方法；Resources是注入给LLM的只读数据，类似RAG检索结果；Prompts是可复用的对话模板。核心区别在于控制方：Tools由LLM触发，Resources由应用注入，Prompts由用户选择。

### Q4："MCP的通信方式是什么？"
> 基于JSON-RPC 2.0协议，传输层支持stdio（本地进程通信）和SSE（Web服务）。Spring Boot环境推荐用SSE方式。连接建立后，Client通过tools/list动态发现Server暴露的工具。

### Q5："MCP解决了什么实际问题？"
> 解决了AI工具对接的N×M问题。没有MCP，每个模型对接每个工具都要单独写代码；有了MCP，工具提供方只需实现一个MCP Server，所有支持MCP的模型都能直接使用。对企业来说，工具开发一次就能服务于多个AI应用。
