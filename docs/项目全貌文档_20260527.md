## 4. 核心模块详解

### 4.1 启动类 `SpringAiDemoApplication.java`

- **排除自动配置**：`ChatClientAutoConfiguration`、`OpenAiEmbeddingAutoConfiguration`
- **双模型配置**：`OllamaChatModel` + `OpenAiChatModel`，通过 `@ConditionalOnProperty(name = "app.chat.provider", havingValue = "...")` 切换
- **Embedding 始终用 Ollama**：`OllamaEmbeddingModel`（nomic-embed-text，本地免费）
- **ChatClient Bean**：`chatClient`（基础对话）、`chatClientBuilder`（Agent 构建用）

**关键踩坑**：`@Primary` 解决多 `ChatModel` Bean 歧义；`ChatClient.Builder` 是可变对象，`.defaultTools()` 会修改自身，必须用 `ChatClient.builder(chatModel)` 工厂方法创建隔离 Builder。

---

### 4.2 控制器层

#### `ChatController.java` — 基础对话

| 接口 | 方法 | 说明 |
|------|------|------|
| `/chat` | GET | 基础对话（非流式） |
| `/chat/role` | GET | 带角色设定的对话 |
| `/api/chat` | POST | 前端 API（非流式 JSON） |
| `/api/chat/stream` | POST | 前端 API（SSE 流式） |
| `/api/chat/clear` | POST | 清空对话历史（删除 Redis Key） |

**内部 DTO**：`ChatRequest`、`ChatResponse`、`ClearRequest`、`ClearResponse`

#### `AgentController.java` — Agent 智能体（最核心）

- **Tool Calling**：注入 `OrderTools`，`defaultTools(orderTools)` 挂载工具
- **ChatMemory**：注入 `ChatMemory`，`MessageChatMemoryAdvisor` 自动加载/保存历史
- **RAG**：`CustomRagAdvisor` 在 Advisor 链中执行向量检索
- **双 ChatClient 架构**：
  - `chatClient`：带 Tool + ChatMemory + RAG，用于普通对话
  - `jsonOnlyClient`：纯净无工具，用于 `/agent/analyzeIntent` 结构化输出
- **接口**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/agent/chat` | POST | 同步对话（带工具+记忆+RAG） |
| `/agent/chat/stream` | POST | SSE 流式对话 |
| `/agent/analyzeIntent` | GET | 意图识别（结构化输出，返回 JSON） |

**System Prompt 五要素**：角色定义、能力边界、行为规则、输出格式、禁止事项

#### `RagController.java` — RAG 检索

| 接口 | 方法 | 说明 |
|------|------|------|
| `/rag/upload` | POST | 上传文档（支持 PDF/DOC/XLS/PPT/TXT 等） |
| `/rag/ask` | GET | 基于向量库回答问题 |
| `/rag/formats` | GET | 查询支持的文件格式列表 |
| `/rag/getDocument` | GET | 获取知识库检索结果（调试用） |

**流程**：文件上传 → 格式识别 → `DocumentReader` 解析 → `OverlappingTextSplitter` 切片 → `EmbeddingModel` 向量化 → `PgVectorStore` 存储

#### `McpClientController.java` — MCP Client 测试

- **条件激活**：`@ConditionalOnProperty(name = "app.mcp.client.enabled", havingValue = "true")`
- **注入**：`ToolCallbackProvider`（MCP Client Starter 自动装配，远程 MCP Server 的工具自动变成 ToolCallback）
- **接口**：`/mcp/chat`（GET）— 测试 MCP 远程工具调用

### 4.3 配置层

#### `ChatClientConfig.java`

- 根据 `app.chat.provider` 开关决定注入哪个 `ChatModel` 作为 `@Primary`
- 创建两个 `ChatClient` Bean：`chatClient`（基础）、`chatClientBuilder`（Agent 构建）

#### `McpServerConfig.java`

- **条件激活**：`@ConditionalOnProperty(name = "app.mcp.server.enabled", havingValue = "true")`
- 自动扫描 `@Tool` 方法，注册 SSE 端点（`/mcp/message`）
- **踩坑**：有 `spring-boot-starter-web` 时必须用 `webmvc` 版 Starter（而非 webflux），否则 `/sse` 路由不注册 → Client 连接 404

#### `RedisChatMemoryConfig.java`

- **RedisChatMemoryRepository**：手写实现 `ChatMemoryRepository`（Spring AI 1.0.x 原生不支持 Redis）
- **SummarizingChatMemory**：装饰器模式，`SummarizingChatMemory` → `MessageWindowChatMemory` → `RedisChatMemoryRepository`
- 触发压缩条件：消息数 > 20 条

#### `RedisChatMemoryRepository.java`（302 行，最复杂文件之一）

- **Redis 数据结构**：Key = `chat:memory:{conversationId}`，Value = `List<String>`（JSON 序列化）
- **序列化方案**：Jackson + DTO 中转（`MessageDto`、`ToolCallDto`、`ToolResponseDto`）
- 支持 `ToolCalling` 消息的序列化/反序列化（最常见的复杂场景）

---

### 4.4 服务层

#### `RagService.java`（237 行）

- **支持格式**：PDF、DOC、DOCX、XLS、XLSX、PPT、PPTX、TXT、HTML、HTM、MD、CSV、JSON、XML
- **处理流程**：
  1. 文件上传 → `MultipartFile` 接收
  2. 格式识别 → 根据文件扩展名选择 `DocumentReader`
  3. PDF → `PagePdfDocumentReader`；其他 → `TikaDocumentReader`
  4. `OverlappingTextSplitter` 切片（chunkSize=500 token，overlap=10%）
  5. `EmbeddingModel`（Ollama nomic-embed-text）文本转向量
  6. `PgVectorStore` 存储到 PostgreSQL
- **相对分数过滤算法**（`filterByRelativeScore`）：
  - top1 score < 0.45 → 全部拒绝（绝对值兜底）
  - top1 - top2 < 0.08 且 top1 < 0.7 → 全部拒绝（无区分度）
  - 只保留 score > top1 × 0.85 的 chunk（与最高分相差不超过 15%）

---

### 4.5 Advisor 层

#### `CustomRagAdvisor.java`（162 行）

- 实现 `BaseAdvisor` 接口（1.0.5 推荐方式，旧版 `CallAroundAdvisor` 已废弃）
- **执行链路**：`before()`（向量检索 + 注入上下文） → `chain.nextCall()` → `after()`（记录 Token 用量）
- **Advisor 顺序**：`MessageChatMemoryAdvisor.order = Integer.MIN_VALUE + 1000`（先执行，加载历史）；`CustomRagAdvisor.order = 0`（后执行，RAG 检索时已能看到历史消息）
- `augmentSystemMessage()` 是追加不是替换 system prompt

---

### 4.6 记忆层

#### `SummarizingChatMemory.java`（135 行）

- 带摘要压缩的 `ChatMemory` 实现
- **触发条件**：消息数 > `MAX_MESSAGES`（20 条）
- **压缩逻辑**：前半段消息 → LLM 生成摘要 → 摘要（1 条）+ 近期消息（10 条）
- 使用**纯净 ChatClient**（无工具）专门用于 LLM 压缩，避免 Tool Calling 干扰

### 4.10 转换器层

#### `OverlappingTextSplitter.java`（233 行）

- **两层切片法**：
  1. 第一层：`TokenTextSplitter` 粗切（chunkSize × 2，保留语义块）
  2. 第二层：滑动窗口细切 + overlap（相邻切片有重叠，防止边界语义断裂）
- **默认参数**：chunkSize=500 token，overlap=10%（50 token）
- **断开点优先级**：换行符 > 中文句号/问号/感叹号 > 英文标点 > 逗号/分号 > 空格
- **字符/token 比**：2（中文保守值）

## 5. 数据库设计

### PostgreSQL（主数据库）

**向量表**（`pgvector` 扩展自动创建）：

```sql
CREATE TABLE knowledge_vectors (
    id BIGSERIAL PRIMARY KEY,
    content TEXT,               -- 原始文本
    metadata JSONB,             -- 元数据（来源文件、页码等）
    embedding VECTOR(768)       -- nomic-embed-text 产出 768 维向量
);
CREATE INDEX ON knowledge_vectors USING ivfflat (embedding vector_cosine_ops);
```

**业务表**（见 `src/main/resources/data/init-data.sql`）：

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `orders` | 订单表 | order_id, user_id, status, logistics_status, total_amount, create_time |
| `products` | 商品表 | product_id, product_name, category, stock, price, description |
| `aftersale_tickets` | 售后工单表 | ticket_id, order_id, user_id, type, reason, status, resolution |

### Redis（ChatMemory 存储）

| Key 格式 | 类型 | 说明 |
|----------|------|------|
| `chat:memory:{conversationId}` | List<String> | 消息 JSON 列表，每个元素是一条消息的 JSON |

### 技术深度亮点（面试高频追问点）

| 亮点 | 说明 | 面试价值 |
|------|------|----------|
| **双 ChatClient 架构** | `chatClient`（带工具）+ `jsonOnlyClient`（纯净），解决 Tool Calling 污染结构化输出问题 | ★★★★★ 高频追问 |
| **手写 Redis ChatMemory** | Spring AI 1.0.x 原生不支持 Redis，手写 `RedisChatMemoryRepository`，Jackson DTO 中转序列化 | ★★★★ 亮点 |
| **CustomRagAdvisor 相对分数过滤** | 不止用绝对 threshold，用 top1-top2 分差判断是否拒绝，召回率 60%→90% | ★★★★ 量化数据 |
| **MCP webmvc/weblux 踩坑** | 有 Tomcat 时用 webmvc 版 Starter，用 weblux 版会 404，根因是 Spring MVC 不注册 webflux 的 `/sse` 路由 | ★★★★ 踩坑故事 |

| **OverlappingTextSplitter 两层切片** | 粗切保留语义块 + 细切滑动窗口 overlap，防止边界语义断裂 | ★★★ 细节 |

### 面试 1 分钟介绍话术

> "这是一个基于 Spring AI 1.0.5 的智能客服系统。核心功能有三个：
> 第一，RAG 检索增强——用户提问时先从 PostgreSQL+pgvector 向量库检索相关文档，再让 LLM 基于文档回答，我还做了相对分数过滤算法，把召回率从 60% 提升到 90%；
> 第二，Agent 智能体——通过 Tool Calling 让 LLM 主动调用订单查询、库存查询、售后申请等工具，支持多轮对话记忆，记忆存在 Redis；
> 第三，MCP 协议集成——把工具通过 MCP 标准协议暴露出去，其他 AI 应用也能调用我的工具。
> 项目里我踩了不少坑，比如 ChatClient.Builder 是可变对象这个问题，以及 MCP webmvc/weblux Starter 不兼容的问题，都是看了源码才解决的。"
